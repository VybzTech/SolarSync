Gemini: Bottleneck Review & Risk Mitigation
Building an IoT energy monitoring app isn't just about writing code; it’s about managing third-party platform gatekeepers and hardware realities.
A. The iOS & App Store Ecosystem Bottlenecks
The Risk: Apple reject rate for first-time hardware/IoT connected apps is high if prerequisites aren't set up early or if test credentials aren't provided to review teams.
Apple Developer Organization Account Setup:
 The Trap: Setting up an Apple Developer Organization Account requires a D-U-N-S Number for FoliVision, legal entity verification, and can take 2 to 4 weeks if not started immediately.
 Mitigation: Request FoliVision to kick off their Apple Developer Organization registration on Day 1.
 TestFlight & App Review Guidelines (Section 2.1 & 5.1):
 The Trap: App Store reviewers need to test real data flow. If they can’t log into an active inverter demo account, they will reject the build.
 Mitigation: Create a dedicated Demo/Staging Inverter Environment on SolarmanV5 specifically for Apple App Store reviewers.
 Background Data & Push Notifications:
 The Trap: Apple strictly audits apps using background processing for real-time polling.
 Mitigation: Rely on server-side push notifications (Firebase Cloud Messaging/APNs) triggered by your backend when thresholds are breached, rather than client-side background polling.
B. Hardware & API Bottlenecks (SolarmanV5 & Deye)
 API Rate Limits & Latency: SolarmanV5 APIs often enforce polling limits. Polling every 5 minutes across hundreds of inverters requires backend caching (Redis/JSON server layer).
 Data Logger Connectivity: Inverter Wi-Fi sticks drop offline frequently due to local grid instability or poor router signal.
 Mitigation: Phase 1 MVP must include an "Offline / Stale Data" indicator so users don't blame the app when their physical Wi-Fi stick disconnects.
